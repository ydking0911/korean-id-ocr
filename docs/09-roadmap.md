### 1단계 검증 기록 (2026-10-07, 클라우드 작업 환경)

- rapidocr 휠 동봉 v6 모델로 `IDOCR_REQUIRE_HANGUL=false` 배선 검증: 컨테이너 healthy, `/v1/ocr/raw`가 `900101-1234567`(가짜 번호)을 score 1.0으로 인식.
- v6 rec는 한글이 없어 `require_hangul=true`일 때 기동 거부되는 것 확인 (의도한 안전장치).
- 컨테이너 메모리 약 400MB (워커 2, v6 small 모델 기준). 장당 지연 1~2초는 이 환경(4코어 공유) 기준이라 참고만.
- onnxruntime이 `/tmp/mat-debug-<pid>.log` **빈 파일(0바이트)**을 만든다. 내용 없음, tmpfs(메모리)라 디스크 기록 아님.

### 한국어 모델 검증 (2026-10-07, 클라우드 작업 환경 4코어 공유)

- 기본 조합(v5 mobile det + v5 korean rec + v2 cls) 이미지 빌드 시 SHA256 4개 모두 통과, read-only·non-root로 기동.
- 견본 2장 `/v1/ocr/raw`: 첫 요청 3.4초, 이후 **1.0~1.2초/장**, 메모리 **343MB**.
- 인식 결과와 2단계 영향은 02 문서 4.5절.

## 실물 샘플 확인 (2026-10-07)

사용자가 준 실물 양식 샘플 4장(주민등록증 2019·2022, 운전면허증 2019·2022, 값은 모두 가짜)으로 확인. 이미지는 `samples/real/`(gitignore).

| 문제 | 원인 | 조치 |
|---|---|---|
| 주민번호가 `234567-8`로 잘못 잡힘 | 박스가 `820701` / `2345678`로 쪼개짐, 7자리 숫자를 가려진 주민번호로 오인 | 하이픈 유무 패턴 분리 + 같은 줄 박스 합쳐 재탐색 (`layout.merge_row`) |
| 230px 남짓한 작은 사진에서 오인식 다수 | 글자 높이 10px 수준 | 긴 변 1000px 미만이면 확대 (`IDOCR_MIN_SIDE_LEN`) |
| 날짜 `2019.1 28`, `2033,01.01.` 미인식 | 구분자 누락·쉼표 | 날짜 정규식 완화 |
| `2종보동`, `2보통` 미인식 | 글자 오인식·'종' 누락 | 면허종류 자모 거리 1 허용, 종 생략 허용 |
| `성울병신 종로구` 시·도 실패 | 시·도가 두 글자 이상 깨짐 | 시·군·구가 한 시·도에만 있으면 시·도 역추론 |
| 발급기관이 직인 노이즈(`영록특별시`)로 잡힘 | 발급일과 같은 높이의 직인 글자 | 발급기관 접미사로 끝나는 줄 우선 |
| 발급기관 앞에 `981032` | 신형 좌하단 고스트 이미지의 생년월일 | 한글 없는 앞 박스 제외 |
| 면허 조건 `조`/`건P모` | 작은 글씨 | `건` 누락 허용, 조건에도 text 임계값 적용. `조`까지 빠지면 미검출(null) |

**남은 한계**
- 괄호 안 동 이름(`미12동`, `봉전동`)은 교정하지 않는다. 내장 사전은 **행정동**인데 주소에는 **법정동**(`봉천동`)이 쓰여, 비슷한 행정동(`봉선동`)으로 잘못 바뀐다. 법정동 목록을 `IDOCR_ADDRESS_LEXICON`으로 넣으면 교정된다.
- 2022년 작은 샘플(230px)은 확대해도 주소 둘째 줄 이후가 깨진다 → 미채택(PARTIAL/FAIL)으로 처리됨. 실사용 촬영 해상도에선 문제 아님.
- 2022 주민등록증 샘플(230px)의 이름 `김이땡`을 한글 재인식이 `김이명`(0.92)으로 읽어 **틀린 값이 채택**된다. 저해상도에서 드문 글자(`땡`)를 흔한 글자로 바꾸는 경향 → 재인식 결과가 원래 인식과 다르면 신뢰도를 낮추는 방안 검토.
- 2019 면허 샘플의 주민번호 `000829-2…`는 샘플 자체가 규칙 위반(2000년생은 3/4)이라 무효 판정이 맞다.
