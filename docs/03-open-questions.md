# 03. 미결정 사항 — 추천안과 질문

상태: 🟡 논의 중 / ✅ 결정됨

## Q1. 성인 기준 🟡

| 방식 | 판정식 | 비고 |
|---|---|---|
| 만 19세 (민법) | `오늘 >= 생일 + 19년` | 가장 보수적 |
| 연 나이 19세 (청소년보호법) | `올해 - 출생연도 >= 19` | 청소년유해매체 기준. 1월 1일부터 그 해 19세 되는 사람 모두 통과 |

**추천**: 둘 다 구현하고 설정값으로 선택, **기본값은 만 19세**(더 엄격해서 분쟁 여지가 적음).
역할로 막으려는 콘텐츠가 청소년유해매체 성격이라면 청소년보호법 기준이 법적으로는 정확함.
→ **질문**: 역할로 접근을 제한하는 콘텐츠가 어떤 종류인지?

## Q2. 제출 방식 🟡

| 방식 | 다른 사람 노출 | 원본 메시지 삭제 | 비고 |
|---|---|---|---|
| **슬래시 커맨드 첨부 옵션** | 없음 (채널에 메시지가 생기지 않음) | 삭제할 메시지 자체가 없음 | Message Content intent 불필요 |
| DM | 없음 | **봇이 유저 DM 메시지를 삭제할 수 없음** → 유저 DM에 영구 잔류 | |
| 전용 채널 | 삭제 전까지 노출 가능 (권한 설정 실수 시 위험) | Manage Messages로 삭제 가능, 경쟁 상태 존재 | Message Content intent 필요 |

**추천**: `/인증 image:<첨부>` 슬래시 커맨드 + ephemeral 응답.
첨부는 CDN에 올라가지만 채널 메시지로 남지 않으므로 "판별 후 삭제" 단계가 사실상 불필요해진다.

**추가 제안 — 뒷자리 가림 요구**: 유저에게 **뒷자리 2~7번째를 가리고(스티커/손가락) 촬영**하도록 안내.
정규식은 `\d{6}-[1-8]`만 필요하므로 판별에 지장이 없고, CDN에 남는 이미지에도 전체 번호가 남지 않는다.
→ **질문**: 가림을 "권장"으로 할지, "필수"(가려지지 않은 7자리 이상 연속 숫자가 보이면 거부)로 할지?

## Q3. OCR 실패·저품질 처리 🟡

**추천**:
1. 항상 적용: EXIF 회전 보정(폰 사진 대부분 해당), 긴 변 ~1600px로 축소(속도·정확도), 너무 작은 이미지 거부.
2. 1차 실패 시에만: 그레이스케일+CLAHE 대비 보정, 90°/270° 회전 순으로 최대 3~4회 재시도. 첫 유효 결과에서 중단.
3. 원근 보정(카드 테두리 검출)은 Phase 2 결과를 보고 필요하면 추가.
4. 실패 시 이유별 안내: "번호를 찾지 못함 → 밝은 곳에서 정면 촬영", "형식 오류 → 재촬영". 유저당 재시도 횟수/쿨다운 제한.

→ **질문**: 재시도 제한을 어느 정도로? (예: 10분에 3회)

## Q4. 동시 요청 처리 🟡

- onnxruntime 추론과 OpenCV 연산은 GIL을 놓으므로 **스레드풀로 충분**하다. 프로세스풀은 프로세스마다 모델(~100MB+)을 다시 올리고
  bytes를 프로세스 간 복사하므로 이점이 적다.

**추천**: 전용 `ThreadPoolExecutor(max_workers=W)` + `asyncio.Semaphore` 대기열 + 요청 타임아웃.
`W × intra_op_num_threads ≤ CPU 코어 수`로 맞춘다 (예: 4코어 → W=2, 스레드 2). 대기열이 가득 차면 "잠시 후 다시" 응답.
→ **질문**: 운영 서버 사양(코어/RAM)과 예상 서버 규모(동시 인증 요청 수)는?

## Q5. 저장소 🟡

**추천**: SQLite (`aiosqlite`), 테이블 하나.

```
verifications(guild_id, user_id, status, verified_at, rule_version)
  status: VERIFIED | UNDERAGE | (실패는 저장 안 함, 쿨다운은 메모리)
```

- 생년월일·출생연도는 저장하지 않는다. 대신 미성년 거부 시 "언제 재인증 가능한지"는 알 수 없게 된다 (재제출 필요).
- `rule_version`: 성인 기준·모델이 바뀌었을 때 추적용.

→ **질문**: 미성년 판정 결과도 남길지? (남기면 반복 시도 차단 가능, 대신 "미성년자"라는 민감 정보를 보관하게 됨)

## Q6. 디스코드 라이브러리 🟡

**추천**: `discord.py` 2.7.x — 활발히 유지보수, app_commands(슬래시 커맨드)·ephemeral·첨부 옵션 모두 지원, 자료가 가장 많음.
대안(py-cord, nextcord, hikari)은 이 규모에서 바꿀 이유가 없음.

## Q7. 테스트 🟡

**추천** 3단계:
1. **단위 테스트(핵심)**: OCR 텍스트 문자열을 직접 넣어 추출·판정 검증. 경계값(생일 당일/전날, 윤년, 1999/2000년생, 외국인 5~8).
2. **합성 이미지**: Pillow + Noto Sans KR로 주민등록증 레이아웃을 흉내 낸 가짜 카드 생성 (가짜 이름·번호, "SAMPLE" 워터마크).
   증강: 회전, 원근, 블러, JPEG 압축, 조명 그라데이션, 모니터 재촬영. 정답 레이블은 파일명이 아닌 별도 JSON.
3. **개인정보 회귀 테스트**: 파이프라인 실행 후 `caplog` 전체에 6자리 이상 숫자열이 없음을 단언, 예외 경로 포함.
4. 실물 검증이 필요하면 **본인 신분증을 뒷자리 가린 상태로** 로컬에서만 CLI로 확인, 파일은 커밋하지 않음 (`.gitignore`에 `samples/private/`).
